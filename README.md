# tyskill

帮助使用 AI、判断 AI 产出并承担真实任务的 Skills。

当前发布：`tys-ai-output-acceptance`。

## tys-ai-output-acceptance

AI 可以快速生成内容、代码、网站、数据分析、方案和自动化，但“生成完成”不等于“可以使用”。这个 Skill 会从使用场景厘清表面要求背后的真实需求，与用户确认目标和可观察的验收标准，最后依据证据给出“通过／未通过／无法验收”的结论。

支持两种用法：

- **验收已有产出**：检查已有结果，指出未达标之处并给出修复方案。
- **直接产出并验收**：直接接收任务，确认真实需求和标准后生成产物、检查结果，在授权范围内修复并复测。

它会重点检查：

- 目标和验收标准是否一致；
- 事实、计算、行为、约束和外部动作是否有匹配证据；
- 失败会具体影响谁、造成什么、是否可恢复；
- 未通过时应该修什么、需要什么工具或授权、怎样复测。

模型自查、多模型一致、换模型或接入 MCP 可以帮助发现线索，但不能单独证明产出已经正确。

## 安装

```bash
npx -y skills add twentyy168/tyskill -g --all
```

## 使用

安装后，可以这样开始：

> 使用 $tys-ai-output-acceptance 验收这个 AI 产出，给出通过、未通过或无法验收的证据结论。

也可以直接说：

> AI 帮我做了一个带注册、登录和支付的网站。我不会编程，请帮我验收它能不能上线。只使用测试支付，不要部署。

还没有产物时，也可以说：

> 请帮我做一个收集客户咨询的网站。从使用场景厘清真实需求，与我确认目标和验收标准，再制作、检查和修复。不要部署。

Skill 会先给出真实需求判断、目标拆解和验收标准草案。用户确认后，按请求检查已有产物，或直接生成、验收并修复；缺少证据时明确说明无法验证的原因。

## 适用范围

适合检查已有 AI 产出，也适合按明确目标和标准完成内容、代码、网站、数据、方案与自动化任务。直接产出用法同时包含验收，不以生成完成代替验证通过。不用于训练模型或比较模型排行榜。

医疗、法律、投资、人身安全等高风险专业结论仍需合格专业人员复核。验收请求默认只授权检查，不自动发布、付款、发送消息、连接账号或修改生产系统。

## 运行依赖

- 支持 Agent Skills 的客户端；
- 部分验收任务需要浏览器、项目文件、测试环境、原始信源或专业复核，Skill 会在缺失时明确标为未验证。
