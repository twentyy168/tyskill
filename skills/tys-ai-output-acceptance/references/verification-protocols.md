# 验收协议

只读取与当前产物有关的部分。协议提供最低动作和边界，不保证所有场景都充分。

## 事实与研究内容

1. 将产出拆成可独立真假的原子主张。
2. 对影响结论的主张优先核查，不平均分配时间。
3. 打开原始来源，确认来源真实存在、时间适用、原文确实支持该主张。
4. 数字同时检查单位、分母、时间范围和比较基准。
5. 搜索反方证据或更新材料。

搜索摘要、AI 生成的引用和多个模型的一致回答都不是原始来源。无法访问付费材料或关键原文时标为未验证。

## 代码、网站和 AI 工具

1. 从用户任务写出端到端场景，不要求小白阅读全部代码。
2. 在目标或等价隔离环境启动产物，记录版本和配置。
3. 测试至少一个正常路径、一个边界输入和一个失败路径。
4. 同时观察页面结果、持久化数据、日志、网络请求或测试报告中适用的证据。
5. 涉及身份、权限和数据时，至少测试未登录、普通用户和越权访问中的适用情形。
6. 修复后重跑原失败场景，并回归关键正常路径。

“页面能打开”不能证明业务流程可用；“测试通过”也不能证明未覆盖行为安全。

## 数据、表格和计算

1. 固定输入数据、版本、单位、时区和缺失值规则。
2. 抽取若干行手工或用独立工具重算。
3. 检查空值、零值、负数、极端值、重复值和边界日期。
4. 核对总计与明细、输入与输出行数、筛选前后范围。
5. 区分计算正确、方法适当和业务解释合理；后两项可能需要专业复核。

## 文档、文案与设计

先把主观形容词改写成目标用户任务，例如“读者能否在 30 秒内说出主张和下一步”。分别检查：

- 事实与引用：使用事实协议；
- 格式与硬性要求：使用规则检查；
- 可理解性：让目标用户复述或完成任务；
- 说服与商业效果：小样本发布、访谈或 A/B 测试；
- 审美偏好：由明确的品牌标准或有决定权的人验收。

语言流畅不能证明内容正确，模型评分不能证明真实受众会行动。

### 销售、报名与行动型内容

当产物希望读者购买、报名、预约、咨询或采取其他行动时，额外拆成两条独立主张：

1. **为什么选择它**：目标对象是否能看清自己遇到的问题、方案提供的价值、适用边界、成本与替代方案；
2. **为什么现在行动**：是否存在真实、可核验的时机依据，例如确实存在的开课日期、服务名额、价格结束日、材料截止日、季节性窗口或不行动的明确后果。

验收时：

- 将价值、时间、名额、价格和后果分别列为可核查主张；
- 核对课程安排、库存／排期、公开价格、政策或其他原始记录，而不是相信文案本身；
- 让目标读者复述“适不适合我”和“为什么现在需要决定”；
- 没有真实时机依据时，允许清晰邀请行动，但不能把它包装成紧迫性；
- 将虚假稀缺、伪造倒计时、虚构原价／截止期、无法证明的名额限制，以及把普通延迟描述成必然灾难，标为未通过或需要修复的主张。

## 方案与决策

1. 分开事实、假设、因果判断和建议行动。
2. 核查关键事实；为关键假设寻找反例和失效条件。
3. 估算可逆性、最大损失和退出成本。
4. 能小规模试做时，先定义指标、期限和停止线，再执行试验。
5. 不可逆、高风险或受监管决定交给有资格且承担责任的人批准。

逻辑自洽不等于现实有效。没有现实反馈的方案只能标为待试验。

## 自动化与外部动作

1. 列出触发条件、读取范围、将要改变的对象和接收者。
2. 使用模拟数据、草稿模式或测试账户演练。
3. 验证重复执行、部分失败、超时、权限不足和恢复路径。
4. 设置人工批准点、幂等保护、日志、告警和回滚方案。
5. 未经明确授权，不发送、发布、付款、删除或改动生产系统。

## 证据强度与抽样

证据从弱到强通常为：生成者自述、模型批评、静态规则、独立工具、真实环境运行、目标用户行为、专业复核、持续现实结果。应根据对象选择证据，不机械追求最高等级。

抽样只能支持被抽中的范围。以下情况不能只抽样：关键支付或权限路径、不可逆动作、安全边界，以及一个错误就会改变总体结论的核心事实。
